# Prototype provenance

File: https://www.figma.com/design/u9ZRlQnwfUsErk2bFa9Ceq
Team: Portfolio (chosen by the user)

The six new flows are editable task subsets reconstructed from the supplied case-study evidence, not recovered original Figma files. They do not have production backends. All user, route, policy, parking and code states are prepared examples. They remain drafts.

- Health App: purple routine-goal and scheduling language from `HealthApp/optimized/07-screen-set.webp`; goal → time/day reminder → confirmation.
- Vijay Parivar: orange vehicle-parking screen from `vj/photos/car-parking.png`; fixed sample counts → one available bay → review → confirmation.
- Code for Build: blue Code/Output and block hierarchy from `CodeforBuild/photos/output-code-pair.png`; block → output → illustrative Flutter/Dart.
- Ballah Code: dark file-tree, task conversation and validation-code pane from `BallahCode/site/ballah-product-window.png`; workspace → proposed change → local receipt.
- OrgDashboard: existing case-study concept, explicitly not active according to the user; knowledge → source → review → receipt. No live product claim.
- Raahi: original blue/orange home and route screens from `Raahi/photos/`; prepared home → route list → route detail → sample journey.

No source file was edited. Existing Mentra and MiniApps flows are linked separately, using their original nodes and connections.

Construction scope: six task flows, not a component library or production UI replacement. There were no Code Connect mappings in the portfolio and the new file was empty. No existing compatible local library was present; available system UI kits would have replaced the original project branding. Namespaced project palette variables and the source-appropriate Roboto, Nunito and DM Sans families were used for editable layout construction. `build-task-flows.js` records the initial construction; workspace refinements and contrast repairs are recorded by the final screenshots and audit reports.
